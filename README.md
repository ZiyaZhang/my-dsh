# my-dsh

DeepSeek Harness（DSH）的看板插件原型。它把会话按事项收拢，再加一条叫 my dsh 的会话：能回答问题，把活派给事项里的会话，跟进进度。

## 现在能用的

- 左栏 my dsh。页头是 my dsh，下面一句全局数字“你已使用 dsh N 天，开启 N 个 session，用过 N token，安装 N 个插件”，和下面看板的内容左右对齐；右边背景里一只对着电脑的鲸鱼，用 DSH 的蓝调淡来画、跟着深浅主题换色，站在页头底线上，和看板内容的右边对齐（内容宽不到 660px 时不显示）。token 数来自 DSH 为每条会话缓存的用量，旧格式的会话没有这份记录，不算在内，悬停能看到算进了多少条。下面紧接着是看板和对话两个标签。
- 看板：最上面是 my dsh 的输入框，发出消息后切到对话。输入框下面一张卡片，先列等待回答、等待审批或失败的会话，再列自动归类的建议；只露 3 行，其余收在“还有 N 条”里，什么都没有时不显示。再往下是事项（每件进行中的事项一张卡片，列最近的会话和状态）和回顾（按天列出最近 14 天的会话，最近的一天默认展开）。
- 对话：my dsh 的对话。右边一栏是看板的简版（待处理、事项、今天完成，空的一组不显示），能拖宽窄（300px 到页面的 70%，给对话至少留 400px），双击边线恢复默认宽度，能收起和打开；宽度和开关记在浏览器里。
- 事项页：页头是事项名、目标、会话数和记忆条数，右边是托管下拉（派出去的会话用哪个 DSH 权限预设跑，完全权限要先确认）和菜单（改名、改目标、编辑上下文、归档）。看板标签是事项自己那条对话的输入框、事项的会话和“这件事的上下文”（指令、来源、记忆、产物，点进去分段看）；对话标签是那条对话，右边一栏列事项的会话和上下文。
- 派出去的会话：事项的对话开的会话、发过消息的会话，在那一轮下面各有一张卡片，跟着会话实时显示它在做的这一步、问你的话、报错或回复的开头；等你回答或批准时，链接是“去回答”“去批准”。同一条会话又被派活时，只有最新那张跟着变。
- 事项记忆：每件事项的记忆是一组 Markdown 文件，放在事项主工作区下的 `.my-dsh/<事项 id>/memory/`，按规则、定下的、答过的、坑、没做完分文件夹；`MEMORY.md` 是插件按各文件开头生成的索引，超过 200 行或 16 KB 时最大的一组折进它自己的 `INDEX.md`。事项里的会话每轮读到这份索引，能用 DSH 的文件工具读写这些文件。事项里的会话都停下 2 分钟后，插件用默认模型补记一次；每天整理合并一次。看起来像密钥的文件不进索引，改动记录里也不存它的内容。
- 产物：事项里的会话用 write、edit、apply_patch 写过的文件，按事项列出。
- 自动归类：最近 14 天不在任何事项里的会话，先按来头归（同一个定时任务、同一个 PR、同一个分支、互相 @ 过），剩下的交给默认模型，给出“建事项”和“归进已有事项”两种建议。点开一条看目标、会话、主工作区和理由，点“新起”或“归进”才改；点“不要”的组合以后不再提，手动移出过的会话也不会被建议放回原事项。插件启动时跑第一次；之后散会话有新活动或新建了事项才再跑，两次至少隔 3 小时，没有变化就不跑。接受过的建议能在做事记录里撤回。
- my dsh 是一条用 my-dsh 预设的普通会话：能读文件、找文件，不能写文件、跑命令；它每轮读看板索引，能查会话最近的回复，能把用户的原话转给事项的对话；开会话、给会话发消息由事项的对话做。新建、合并、改名事项它只提议，在卡片上点了才改；说法对不上唯一的事项或会话时，它给出候选让人点选。
- “做事记录”按天列出 my dsh 和自动归类做过的事，以及手动的归类，能撤回的带撤回；有记录以后，看板、对话标签那一行的右边才出现这个入口。撤回一条它开的会话，会停下那条会话，并把它移出事项。
- 会话的右键菜单里能加入事项、移出事项，也能直接新建一件事项把它放进去。
- 在 DSH 自己的会话页打开 my dsh 或某件事项的对话时，右侧栏第一次会出一个 my dsh 或“事项：名字”的标签，“整页看”回到 my dsh 页。
- 状态只来自同一个 DSH 进程：别的进程（比如另开的 profile）正在跑的会话，在这里显示为空闲。

插件往会话里写东西的情况：my dsh 把用户的原话转给事项的对话；事项的对话按用户的话开会话、给会话发消息（给正在跑的会话发的话，它下一步就读到），并要派出去的会话做完时最后一条回复先写清结果。事项托管时，它派出去的会话都停下后，插件叫醒那条对话一次，让它接着派下一步，不复述结果（用户没说话时最多连着叫醒 10 次）；它派用户交代的最后一步时会标出来，那一步正常做完就不再叫醒，失败了照样叫醒。没托管的事项不叫醒，结果看卡片。补记、整理和自动归类在后台用默认模型，没有配置模型时都跳过。

数据在 DSH 数据目录下的 `my-dsh/`（默认 `~/.dsh/my-dsh/`）：`matters.json` 是事项，`assistant.json` 是 my dsh 的会话、做事记录和卡片，`grouping.json` 是自动归类的运行记录、建议和不再提的组合，`artifacts.json` 是产物，`memory-state.json` 等是记忆的整理状态，`corrections.jsonl` 记每次纠正（手动加入、移动、移出、在候选卡上选、拒绝提议或建议、撤回）。这些都只留在本机。事项记忆在事项主工作区的 `.my-dsh/` 里；主工作区是 git 仓库时，插件把 `.my-dsh/` 写进 `.git/info/exclude`。

## 安装开发版

需要 DSH 0.2.2-rc.1 或之后的 0.2.x。

```bash
npm install
npm run build
dsh plugin --profile <profile> add link:/path/to/my-dsh
```

重启这个 profile，左栏就有 my dsh。建议先装进单独的 profile 试，不要直接装进日常用的那个。

## 开发

```bash
npm run check
```

依次跑类型检查、测试和打包。
